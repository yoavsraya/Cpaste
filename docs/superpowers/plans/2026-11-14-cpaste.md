# Cpaste build plan

This plan builds the app described in `../specs/2026-11-14-cpaste-design.md`. It has six phases. Each phase ends in a state you can check on the real app, and the next phase starts only when those checks pass. Check a box only when its evidence exists.

Unit tests alone do not close a phase. Each phase also has a live check against the running app.

## Before you start

- [x] Pick the panel layout. The bottom shelf, option A in `../specs/ui-options.html`, chosen on 2026-11-14.
- [ ] Install Xcode from the App Store and run `sudo xcode-select -s /Applications/Xcode.app`. Evidence is `xcodebuild -version` printing a version.

## Risks

- **Background clipboard reading on macOS 26.** The probe read the clipboard with no prompt, but it ran inside the terminal's process. The built app may be treated differently. Phase 1 checks this first because everything depends on it.
- **Gatekeeper.** Without notarization the friend needs one manual approval. A paid Apple Developer ID removes that step and costs more than the subscription this app replaces.
- **Cmd+1 is taken in browsers.** A global Cmd+1 hides "go to tab 1" in Chrome. You already live with this today. The shortcut setting in phase 4 is the way out.
- **Large images.** A 5K screenshot is several megabytes as PNG. Thirty days of them can reach gigabytes. Phase 4 expiry bounds it, and the settings screen shows the folder size.

## Alternatives rejected

- **Electron or Tauri.** A global hotkey, a non-activating panel, and synthetic paste all need native code anyway, and the bundle is 100 MB larger.
- **JSON files instead of SQLite.** Search over thousands of clips needs an index, and FTS5 comes with SQLite.
- **SwiftData or Core Data.** Neither exposes FTS5 directly, and GRDB keeps the schema in plain SQL.
- **Mac App Store distribution.** The sandbox forbids posting keystrokes to other apps, which removes direct paste.
